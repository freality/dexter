# Adapter telemetry (Stats/Logs) is optional, not a required Adapter method

Live CPU/RAM and logs for `dex dash` (map #10, ticket #12 "Adapter contract") need a new engine↔adapter contract: `proto/adapter.proto` gains `Stats` and `Logs` server-streaming RPCs alongside today's `Apply`/`Destroy`. The question this ADR records is not *what* the RPCs look like but *where they attach*: `pkg/plugin.Adapter` is the Go SDK interface every adapter binary — first-party or, per the Phase 2 plugin-distribution work, third-party — implements to satisfy `go-plugin`'s gRPC bridge. Adding `Stats`/`Logs` there as required methods would be a breaking SDK change: every adapter, including ones already published and distributed via `dex plugin add`, would need to implement them (even as a stub) just to keep compiling.

Resolved instead as a separate, optional extension interface (e.g. `StatsReporter`) an adapter *may* additionally implement. The gRPC server wrapper in `pkg/plugin/plugin.go` type-asserts the wrapped `Adapter` for it; absent, it returns `codes.Unimplemented` automatically, so an adapter author who doesn't care about telemetry writes no boilerplate at all to stay correct.

This also means an adapter binary built and shipped *before* this ticket existed needs no migration story. Its gRPC server is generated from the `.proto` as it existed at build time, which has no `Stats`/`Logs` method registered at the protocol level; when the daemon (built against the new `.proto`) calls `Stats` against it, grpc-go's own dispatcher receives a request for a method/service combination that binary never registered a handler for, and returns `codes.Unimplemented` — standard gRPC wire behavior, not something either side implements. This is independent of `go-plugin`'s own `Handshake.ProtocolVersion`: that field gates the plugin *framework's* wire compatibility (how the two processes multiplex a gRPC connection at all), not which RPCs a given service exposes, so no version bump is needed for adding a method to an existing service.

The upshot: `dex dash`/the daemon see the identical `codes.Unimplemented` whether talking to an old binary that predates telemetry entirely, or a new one that simply opted out by not implementing `StatsReporter` — one code path handles both, with no adapter-version detection anywhere in the daemon.
